# OrC 自动解析与批量导入

OrC 是中文卡面文本自动解析器。图片导入只负责配图，当前不会从图片识别文字。

卡牌库的「批量导入（资料或图片）」支持 JSON、CSV，也支持同时选择资料与图片。没有图片也会建立卡牌。卡名与图片文件名相同，或资料中的 `file`/`src` 指向图片时，会自动配图。

```json
{
  "cards": [
    {
      "id": "example/infantry",
      "name": "示例步兵",
      "cardType": "unit",
      "unitType": "infantry",
      "cost": 2,
      "attack": 2,
      "defense": 3,
      "opCost": 1,
      "keywords": ["闪击", "轻甲2"],
      "text": "部署：对所有攻击力大于2且防御力不大于5的敌方坦克造成3点伤害。"
    }
  ]
}
```

CSV 支持中英文表头、双引号、字段内逗号与换行；字段内双引号写为两个双引号。`effects`、`kwMap`、`kwValues` 可使用 JSON 字段。JSON 卡牌数组、`{cards:[...]}`、单张卡牌对象都可以导入。额外元数据会保留。

整批先建立卡牌索引，再解析效果；生成/召唤的衍生卡可以写在引用者后面。卡名必须精确且唯一；缺少衍生卡、卡名歧义、未知句子、无效效果不会被当作完整解析。

解析成功的卡进入卡池。未完整解析的卡保存到待核对列表，保留原文、诊断与效果草稿，重启后仍可继续编辑。它们及依赖它们的新卡暂不进入对战卡池。完整解析或修改并核对效果后可以保存入库。相同 ID 的已有卡不会被重新导入覆盖；要调整已有卡，请使用编辑器。批次内重复 ID 会报错。

“自动解析通过”表示文本和效果结构通过检查，并不等于所有实际对战行为已经验证。复杂的研发、牌堆操作、战斗修正等仍可能使用旧动作；报告会列出这些动作。当前卡池审计见 `dist/orc-pool-audit.json`，它是本项目现有卡牌的结果，并非原版全卡覆盖率。

## 自动化命令

```powershell
node tools/orc/import-cards.js --input cards.csv --output ready.json --report report.json
```

输出只包含通过检查的卡牌；报告保留未完成的卡与原因。使用 `--pool dependencies.json` 提供已有衍生卡，使用 `--atomic-only` 要求全部动作都已拆为基本原语。程序只写指定输出与报告，不修改输入或玩家卡池。

退出码：`0` 全部通过；`2` 有待核对或错误条目，但输出与报告已生成；`1` 文件或执行错误。可直接接入后续卡牌资料转换流程。

## 实现与验证

`js/orc.js` 将触发、目标、条件、数值和动作分别解析。比较谓词、查询计数、当前属性、四则计算和循环使用共享原语系统；随机目标会先保存，后续“其”继续指向同一单位。不能完整识别的新语法退回兼容解析，兼容产物仍检查目标引用、动作与卡牌依赖。

旧 `KG.compiler.compile` 接口保留，新的编辑与导入使用 `KG.OrC.compile` / `compileForImport`。`js/card-import.js` 只生成导入计划，界面负责保存；保存失败时回滚卡牌清单，成功后才更新内存卡池。PC 和手机共用相同解析与导入模块。

```powershell
node tools/orc/check.js
node tools/orc/check-cli.js
node node_modules/electron/cli.js tools/orc/check-ui.js
node tools/orc/audit.js
```

测试使用独立玩家目录，不修改实际卡牌与存档。

## 官方全卡语料与覆盖率

`tools/orc/corpus/official-raw.json` 保存 2026-10-03 从 [官方卡牌收藏](https://www.kards.com/zh/decks/collection) 获取的 1,646 条记录，包含现役、预备、衍生及流亡牌。保存了原始多语言文本和元数据，没有下载卡图，也没有导入玩家卡池。

```powershell
node tools/orc/fetch-official.js
node tools/orc/audit-official.js
node tools/orc/audit-official.js --require-complete
```

抓取逐页检查记录总数和唯一性；失败不会覆盖已有语料。审计输出 `dist/orc-official-audit.json`，包含语料 SHA256、每张卡的原文、诊断及尚未拆解的旧动作。`--require-complete` 在任意记录不能导入时返回 2，当前仍不通过。

OrC 4 当前结果：874 条通过结构与能力检查，714 条只使用基本原语；包含衍生卡、老兵形态依赖检查后，821 条可以进入导入输出，825 条待核对。这里的通过数不代表全卡实际结算已经验证；全语料的 `runtimeVerified` 保持 0，实际结算测试单独列在 `tools/orc/check.js`。

本轮接通的通用组合包括：选定单位及其物理相邻单位、筛选抽牌并记录真实手牌实例、逐个计算七种对战词条、手牌属性和花费修改、指定弃牌、手牌回卡组及位置调整、卡池候选选择与生成、抉择分支独立目标、完整能力授予、属性相等和一次交战。没有使用特定卡名的效果配方。卡组实例可以保留修正；旧牌堆强化不再把同名的多个实例重复加到同一个全局定义上。

仍待完成的主要类别：延迟和跨回合对象引用、海军分类及相关操作、钳击、老兵升级条件、更多手牌/牌堆事件、复杂随机伤害与替换流程。官方资料中的卡名差异、缺失依赖和未知元数据仍会阻止自动接受，不能用空效果或猜测配方掩盖覆盖缺口。


卡牌生成编辑（OrC 4）：

- `createCard` 在检查器中显示为「加入手牌」，直接生成指定卡牌，旧数据兼容。
- `threeChoice` 显示为「三选一」：`mode: fixed` 按 `pool.cardIds` 顺序展示最多三张指定牌；`mode: random` 从指定卡池随机取最多三张不同的牌，再选一张加入手牌。
- `developCard` 显示为「开发」：从指定卡池随机展示最多三张不同的牌，选择后生成副本，并派发 `developed` 事件。卡组来源不会移走原卡。
- `pool.source` 支持 `cards`（明确的 ID 列表）、`pool`（完整卡池）、`deck`、`hand`、`discard`；`pool.where` 使用通用属性谓词。可配置卡池归属、是否包含衍生牌和预备牌；隐藏的敌方手牌不能作为候选来源。
- 指定 ID 允许有意使用衍生牌、预备牌。随机隐式卡池默认排除它们，可在界面中开启。重复 ID 在抽样前去重；不足三张时展示实际候选；空池不打开选择、不生成卡牌、不派发开发事件。
- 候选存在但手牌已满时，选择仍完成，开发事件仍发生，加入结果为 `[]`。`as` 记录实际新手牌实例，可供后续费用、属性修改使用。
- 两个选择动作都可在检查器「展开为基本动作」后逐步编辑：选择并记录卡牌 → 读取所选 ID → 加入手牌；开发额外使用通用「触发事件」原语。`atomicOnly` 自动递归展开，包括分支、循环和授予的子效果。
- 候选 ID 参与缺失引用、依赖链和联机同步检查，缺失卡不会被自动接受。检查器卡名搜索不会改变卡池或重建正在输入的文本框。

验证：PC、手机端分别 56 项 OrC 回归、21 项原语回归、72 项战斗规则回归；检查器测试覆盖指定卡池、搜索焦点、保存、随机卡组来源、缺失卡池拦截及拆分撤销。全原版卡语料的导入就绪数仍为 821，未宣称所有原版卡结算验证完成。
