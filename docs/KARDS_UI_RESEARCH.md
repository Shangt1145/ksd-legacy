# Electron 版 KARDS UI 与操作体验调研

> 此文保留修改前的调研结论；已实施的界面与操作调整见 [KARDS_ALIGNMENT.md](KARDS_ALIGNMENT.md)。

调研日期：2026-10-02。范围：当前 Electron 桌面版；Kotlin 不在本轮范围内。此文是调研与改进建议，尚未实施 UI 修改。

## 结论

优先处理战场的信息布局、拖拽反馈和动画衔接。当前版已经有桌布、扇形手牌、指向箭头、落点提示、取消回弹和兵种动画；继续堆叠装饰的收益小于统一这些交互。

参考以官方 2023 年整体 UI 更新、2024 年战斗 UI 更新为主要依据，并用 2026 年官方更新说明补充状态反馈。旧截图只作历史参考，不作为“当前原版”的唯一标准。未运行原版客户端，因此不声称掌握它的精确动画时长、鼠标阈值或所有控件坐标。

## 当前桌面版的对照结果

检查对象是 `dist/win-unpacked/resources/app/game`，没有将废弃的 `Gamme` 作为本轮运行或修改目标。查阅 `index.html`、`css/style.css`、`js/ui.js`、`js/animate.js`，并通过 Computer Use 查看了当前 Electron 的实际换牌画面。

### 画面上已观察到

- 我方指挥点在资源行和底部操作区重复出现。
- 顶栏通过 transform 收起后，原布局仍可能留下空白；在窗口截图中可见顶部空白带。
- 侧栏收起后还露出一条内部控件，并可因悬停展开，战场右侧容易被设置面板干扰。
- 资源、牌库和反制多以带边框的小盒子排列，像工具面板；总部使用统一红底盾牌符号，缺少卡面身份感。
- 结束回合位于左下角。后续可研究将其移到右侧并与左下资源分离；这属于本项目布局建议，尚未实测原版控件坐标。
- 在换牌阶段，现有几张手牌与巨大的战场空区之间比例不协调。正常对局的密集阵线和满手牌仍需专项实测。

### 代码中已确认

| 位置 | 已有能力或差异 | 后续处理 |
|---|---|---|
| `ui.js`：`beginCardDrag`、`onPointerMove` | 按下反馈、6px 拖拽阈值；单位和部分手牌使用箭头 | 保留能力，测试悬停到拖拽的连续性。6px 是本项目值，并非原版实测。 |
| `ui.js`：`highlightValidTargets` | 仅处理 `payload.kind === 'unit'` | 扩展到指向性手牌，过滤依据复用现有规则。 |
| `ui.js`：`cancelDrag`、`flyGhostBack` | 已有 Esc / 右键取消与回弹 | 保留，不重复建设。 |
| `ui.js`：`serializeAction` | 动作按 Promise 链串行结算 | 研究忙碌态与输入反馈；队列执行前重新校验卡牌身份与目标，避免使用变化后的手牌索引。此处是待验证风险，不是已复现 bug。 |
| `ui.js`：`layoutHandFan` | 已有角度封顶 ±7° 的扇形手牌 | 测 1、5、10 张时的间距、悬停遮挡和边缘卡命中。 |
| `ui.js`：`renderBattle` | `st.over` 后立即移除沉浸模式 | 结束后保留最终布局，改用明确的复盘和返回操作。 |
| `ui.js`：卡牌 `contextmenu` | 内置卡右键直接切换异画 | 保留既有功能，先定义检视与异画操作的分工。 |
| `animate.js`：`ANIM` | fly 420ms、lunge 150ms、die 380ms、move 360ms；另有 normal / fast / faster 倍率 | 集中调校；这些是本项目当前值，不是官方参数。 |

实际窗口检测到人工操作后已停止发送输入。本轮没有完成部署、攻击、整局结束的鼠标手感对比，也没有修改卡组或游戏规则。

## 建议的实施顺序

### 第一轮：战场布局与状态

1. 统一我方指挥点到左下主控区，移除重复显示，加入扣费与回合补充反馈。
2. 战报做独立的左侧入口，设置改为点击展开；收起时隐藏内部控件，避免鼠标路过弹出。
3. 修复收起顶栏后仍占布局高度的问题。给战场、手牌与操作区明确的高度预算，先保证不裁切、不滚动。
4. 区分可出牌、可行动、等待目标、不可用状态；以费用数字和轻量边缘提示为主。
5. 对局结束保留最后战场和战报，返回、新局均为明确操作。

### 第二轮：操作连续性

1. 手牌悬停有稳定的可读预览，鼠标移出后平滑恢复；不要影响实际落点命中。
2. 单位部署时显示插入位置，邻牌预让位；确认落点后才播放落地反馈。
3. 指向性手牌与单位攻击统一使用“合法候选 → 当前锁定 → 松手确认”的提示流程。
4. 无效落点回弹，并给出短原因；取消和无效动作都不得扣费。
5. 结算过程中立即反馈输入。是否允许缓冲下一步，必须先验证身份校验和串行规则，不单纯追求更快。

### 第三轮：材质与演出

完善纸张、卡背、总部身份与兵种声音；减少大面积金边、通用震屏和无意义粒子。演出时间先沿用当前配置统一节奏，再依据录屏调校，不能把“更慢”当成“更像原版”。

### 后续：卡组库与构筑

参考新版的右侧卡组概览、搜索与筛选入口、选卡预览。卡组方向变化会影响现有操作习惯，应在战场首轮稳定后单独评估；DIY 编辑器、异画对位与 Inspector 保留各自入口。

## 首轮验收与补充调研

- 1280×720、1440×900、1920×1080 与 Windows 125% / 150% 缩放；5 / 10 张手牌，空 / 满阵线。
- 部署、移动、单位攻击、总部攻击、指向 / 非指向指令、反制、取消、非法落点、连续输入。
- 画面不裁切，费用数字可读，唯一资源主显示明确；拖拽时所有合法目标均能识别。
- 布局变化不能改变费用、相邻关系、目标合法性、回合次序与联机同步。
- 原版 PC 客户端或近期完整实战录屏仍需补充：悬停延迟、拖牌锚点、瞄准箭头、命中瞬间、连续操作、结束回合位置与收尾节奏。官方帮助页只能确认交互含义，不能替代这一层实测。

当前没有可信的原版毫秒级测量，因此暂不制定“完全一致”的动画指标。
