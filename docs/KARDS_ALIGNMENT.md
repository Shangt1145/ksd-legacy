# Electron 规则与操作调整记录

日期：2026-10-02。仅修改 Electron。基础代码取自当前 `dist/win-unpacked/resources/app/game`，维护副本位于 `electron/game`，未使用废弃的 Gamme。

## 本轮边界

按用户最新指定保留以下 DIY 内容：

- 巡航舰、巡地舰、太空战机。
- 磁反应装甲 X、海绵装甲、强磁护盾、轻甲 X、游击、充能 X。
- 已修改的天气与预报链：薄雾、狂风、落雪及其天气引子。
- 支援阵线最多 6 个单位，总部不占单位名额。

其它通用机制按能确认的原版规则调整。保留现有卡池、数值、美术及用户数据；本轮没有重写每张自定义卡的内容。协力是原版机制，予以保留。[官方 Homefront 更新](https://www.kards.com/zh/news/homefront-patch-notes)

## 已落地的规则与效果

| 项目 | 新行为 |
| --- | --- |
| 资源与容量 | 自然指挥点上限 12，手牌上限 9；支援 6、前线 5。明确的容量修正参与部署、移动和加入战场判定。 |
| 伤害计算 | 永久增益只计算一次；主动攻击、反击和伏击使用双方各自的目标修正与天气修正。 |
| 战斗事件 | 零实际伤害不触发受伤；双方存活都派发存活事件；互伤先扣双方生命，再处理死亡，避免亡计在两次扣血之间插入治疗。 |
| 触发范围 | 本单位攻击、受伤与被攻击仅触发自身能力；被攻击能力在伤害前结算。友方与敌方攻击监听保持各自视角，兵种与词条限定作用于事件主角；不符合限定的反制继续挂起。 |
| 守护与伏击 | 支援阵线邻接包含总部位置；条件伏击读取守方限制，判定不会删改守方词条。 |
| 行动 | 普通同阵线拖动不再免费换位；坦克能移动后攻击，普通奋战步兵移动后消耗行动；游击按 DIY 定义保留行动。 |
| 抑制、压制 | 抑制关闭卡面能力和旧授予能力，后续新授予能力仍能生效；免疫时不派发成功事件；压制保持到拥有者下回合结束。 |
| 次数与条件 | 条件失败不消耗一次、一回合一次或充能；支持事件出现早于监听单位入场的首次计数，以及按回合重置的首次计数。 |
| 临时效果 | “本回合”增益在当前回合结束时移除，包括敌方目标。 |
| 动员、山地 | 动员在拥有者回合开始获得 +1/+1，实际受伤后失去；山地根据其它友方山地单位增加数值，也适用于直接加入战场。 |
| 打捞、流亡 | 打捞在己方回合击杀后获得被击杀单位的 1/1 副本，费用最多 3；流亡不再错误地代表死亡或使用后移出游戏。 |
| 隐蔽 | 操作费为 1，通常目标选择排除隐蔽单位；攻击与被攻击揭露；隐蔽部署不消耗通常的部署拦截反制。 |
| 部署与加入战场 | 直接加入战场不执行单位自己的部署能力；额外授予的部署、移动、死亡与监听能力走对应触发路径，避免漏触发或重复执行。 |
| DIY 回归修复 | 充能即时效果每轮只执行一次，多段效果全部完成后才重新计时；抑制后不会从旧文本重建充能或护甲。 |

规则依据：[官方玩法](https://www.kards.com/how-to-play)、[手牌](https://support.kards.com/hc/en-us/articles/360026500332-Battlefield-elements-Hands)、[守护](https://support.kards.com/hc/en-us/articles/360026238532-Unit-ability-Guard)、[奋战](https://support.kards.com/hc/en-us/articles/360026228852-Unit-ability-Fury)、[Winter War](https://decks.kards.com/news/winter-is-here-winter-war-has-arrived-in-kards)、[隐蔽说明](https://www.kards.com/news/exploring-covert-mechanics-in-covert-operations)、[首次触发澄清](https://decks.kards.com/news/august-2025-update-patch-notes)。详细证据与历史规则年代保留于前述调研报告。

## 已落地的界面与交互

- 结束回合按钮移至战场右侧，指挥点集中在右下，减少重复显示。
- 主战场顶部不再预留整行工具栏空间；设置侧栏通过按钮明确展开或收起。
- 攻击拖拽、移动落点、指向性手牌只高亮引擎允许的目标。
- 烟幕单位可以成为通常的指令目标；隐蔽按其效果免疫规则过滤。
- 行动费用浮动反馈绑定实际可见的资源控件；打捞的弱化副本在手牌中显示 1/1。

布局和反馈参考 [官方战斗 UI 更新](https://www.kards.com/news/spring-release-battle-ui-enhancements)。未声称复刻原版客户端的精确动画时间或鼠标阈值。

## 验证和仍待核实的范围

`node tools/dsl/check-kards-compat.js`：72 个合成回归场景通过，覆盖伤害、行动、时点、容量、词条和保留的 DIY 行为。`KG_GAME_DIR` 可以指向便携版 `resources/app/game` 验证实际运行文件。

`tools/check-desktop-ui.js`：实际隐藏 Electron 窗口中检查 1440×1000、1280×800 布局、拖拽高亮、侧栏展开与收起、页面运行错误。使用临时用户目录和合成对局。

原版公开资料尚不足以证明全部边界，以下仍未宣称完全一致：复杂连锁的异步结算顺序，Fight 对伏击、冲击与各兵种的完整组合，炮兵作为守方和轰炸机对战斗机的全部边界，先手首次抽牌，以及支援已满时原版强制撤退的精确结果。首次计数目前基于事件类别和事件方，自身受伤另按单位记录；带兵种或复杂条件的“第一次”不能据此宣称逐卡完全一致。

流亡还涉及建卡国籍规则，自定义卡的原国籍映射没有可靠来源，本轮未虚构映射。原版隐蔽的特殊指定互动也需逐卡实现。本轮是已验证差距的修复和第一批操作改进，不是原版全部卡牌的兼容认证。

旧效果文件把“本单位攻击”和“友方单位攻击”都存为 attack，通常可由卡面区分；同一张旧卡同时含这两类能力时，需要在制卡界面重新解析，以写入明确的触发范围。同步不会自动重编所有卡牌，避免覆盖手写效果。

同步用 `npm run desktop:sync`，只覆盖维护代码并备份旧代码；不重新生成卡池或读取玩家存档。便携运行目录已更新，旧 ZIP / 安装包需要用新的构建命令重新打包。
