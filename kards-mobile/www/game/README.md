# KARDS DIY 对战游戏

用你自己的 262 张 DIY 卡牌，打一场能正常结算特效与词条的对战。

- **怎么打开**：双击 `game\启动游戏.cmd`（会自动找空闲端口、开浏览器；窗口关掉即停服务）。
  也可以手动 `node game/tools/serve.js 8731`，然后访问 **http://127.0.0.1:8731/game/index.html**
  （注意要带 `/game/index.html`，只写 `/` 会 302 跳过去，这是为了避免相对路径 404）。
  或者直接双击 `game/index.html`：能玩，但浏览器禁止 `file://` 页面保存卡组与导入的卡图。
- **卡池来源**：`H:\Working Folder\kards` 下的 262 张 PNG 卡图，逐张转写为结构化数据后编码成可执行效果。

## 3.31 修「拖拽攻击不了单位」

你报的现象：拖自己的单位到敌方单位身上，什么都不发生。

**根因**：上一轮落点判定改成了"先看格子、再看单位"（因为单位卡现在长在格子/槽位里），于是光标压在敌方单位卡上时，
命中的是它所在的那个**格子** → 判定成"放到那个格子" → 那是敌方阵线 → `applyDrop` 直接静默 `return false`。
拖拽攻击整条路就断了（拖到自己人身上、部署、移动都还正常，所以不容易发现）。

**修法**：`dropInfoAt()` 判定顺序改成 **单位卡 → 总部 → 插位**（先看光标下是不是 `[data-uid]` 的卡，
再看 `[data-hq]`，最后才按几何位置算"插到第几格"）。另补两道保险：

- 拖单位时**提前高亮所有能打的目标**（红框 `.can-hit`），不用猜往哪放
- 放到无效位置时给出明确 `toast`（"要攻击就把单位拖到敌方单位/总部上"），不再静默失败

**为什么测试没抓到**：`uitest` 的影子 DOM 选择器只支持 `#id`/`.class`/`[attr]`/`tag` 单独形式，
`.card[data-uid="x"]` 这种组合**永远返回 null**；而且旧断言是直接调 `applyDrop(...)`、跳过了"落点判定"。
现在影子 DOM 支持组合选择器，并用 `docRoot.__at = () => 元素` 伪造 `document.elementFromPoint`，
新增断言把**整条拖拽链路**跑通：*按下→移动→松手＝攻击命中（高亮 5 个可打目标，目标 6→3）*、
*落点判定：拖单位到敌人卡上会解析成「攻击」*、*落点判定：拖到敌方总部上会解析成总部目标*。

## 3.30 场上卡牌居中排列 + 拖拽自动让位 + 非游击单位不能退回支援线

按你的说明改了三处：

- **场上卡牌默认居中**：阵线不再是"一排空槽位框"，而是居中的一排卡（`.line-units{justify-content:center}`）——
  **总部也算这张队伍里的一张卡**（放在队伍最前面），所以 2 个单位时是「总部＋2 单位」整排在中间，
  而不是总部贴左、单位在右边。前线的两排同样居中。
- **拖拽时自动让开位置**：拖着手牌经过某个位置时，那里会插进一个**绿色虚线占位格**，后面的卡自动右移，
  松手就插在那儿（`showGap()` + 用光标 x 与各卡中心比较算出插入下标）。选位模式下每条阵线显示 `n+1` 个
  「＋」插入位，点哪个放哪个位置。位置仍然只是"插到第几个"，空线时点哪都一样（阵线不留空隙）。
- **非游击单位无法回到支援阵线（除非被撤退）**：`KG.canMove(...,'support')` 对没有「游击」的单位直接拒绝，
  界面上前线普通单位不再显示"撤回支援线"按钮（改成一行说明）。**「撤退」效果不受影响**——
  它走 `OPS.returnToHand`（前线→支援线，支援线→手牌），不经过 `canMove`；效果驱动的强制移动也可以传
  `KG.move(..., {byEffect:true})`。

**顺手修掉一个静默 bug**：卡面数据里写着 `{"op":"retreat"}`
（MR-40「成为指令的目标时，撤退至手牌中」），但 `OPS.retreat` **根本不存在**，只会打一条「未实现的效果」日志、什么都不做。
现在 `retreat` 是 `returnToHand` 的别名，并且加了一条 **op 静态自检**：扫描覆盖层 + 编译器产出里用到的**所有 op**，
逐个检查 `KG.effects.OPS[op]` 是否存在（之前只有这样才会发现这类"写了个没人实现的 op"）。

断言：*非游击单位不能自己退回支援线，「撤退」效果可以把前线单位退回（支援线→手牌）*、
*op 自检：数据与编译器产出的每个 op 都有实现*、UI 冒烟里的 *阵线单位默认居中排列*、*选位模式：会出现"可插入位置"占位*；
*移至前线效果* 那条也改成"被撤退后再上前线才再 +1"。

## 3.29 KARDS 化改造：拖拽修好 + 槽位摆放 + 总部做成卡 + 固守相邻 + 卡牌动画

你报的「没法拖拽卡牌」的根因：原来用的是 HTML5 `dragstart/drop`，而**卡面里的 `<img>` 会被浏览器当成
原生拖拽源**——鼠标按在卡图上启动的是"拖这张图片"，我们自己的拖拽数据经常根本传不出去（触摸屏更是完全不触发）。

- **拖拽全部改成指针事件自己算**（`pointerdown/move/up`）：移动超过 6px 才算拖拽，否则当成点击；
  拖动时跟着光标一张卡影、落点高亮；松手用 `elementFromPoint` 找落点。
  - 手牌 → 拖到**槽位**出牌、拖到敌方单位/总部＝指向性出牌、拖到棋盘别处＝指令直接打出
  - 自己的单位 → 拖到阵线＝移动、拖到敌人＝攻击（攻击会先"撞过去"再结算）；
    在同一排里拖到别的格子＝**换个位置**（免费、不消耗行动）
- **部署/移动可以自由选位置**：阵线画成一格格的**槽位**，单位按位置落格。放哪一格就插到哪个位置
  （阵线是"左对齐无空隙"的，所以选的是**插入位置**）。不方便拖拽时：点手牌进入**选位模式**
  （槽位变金色）→ 点空槽位放下；点场上某个单位＝插到它前面；再点一次手牌＝取消。
- **总部做成一张卡**，放在**支援阵线的最左端**（双方都是），可以点（当目标 / 攻击目标）也可以被拖上去。
- **固守只守护左右相邻的目标**：同一条线上，固守只挡得住紧挨它左/右的那个目标，隔开的不受保护；
  因为总部在最左端，所以只有"支援线第一个"的固守守得住总部（`KG.RULES.guardAdjacentOnly`）。
- **卡牌动画**：部署弹入、上前线/撤回滑入、攻击冲刺＋命中闪光＋飘伤害数字、指令卡飞到棋盘中央闪一下；
  掉血/回血仍用逐帧对比上色。全部是 CSS 动画，不妨碍操作。
- 前线也改成两排槽位（敌方在上、我方在下），拖拽时能看出会落在第几个位置。

断言：*槽位：部署可以指定位置*、*固守只守护左右相邻的目标（隔开的单位不受保护；总部只在紧邻时被守护）*、
UI 冒烟里的 *拖拽手牌到指定槽位可以出牌*、*部署位置可控*、*点空槽位/点场上单位也能放置*。

## 3.28 「将X加入手牌」拿不到卡（报「卡池中找不到『undefined』」）已修

你报的现象：`将XX加入手牌` 打出来提示「卡池中找不到「undefined」」，效果不生效。

**原因**：原语里有三条**不带卡名**的通用规则（`/加入手牌/`、`/洗入卡组/`、`/召唤|加入战场/`），它们排在
「将N张卡名加入手牌」这类带卡名的规则**前面**，于是把卡名的位置整个吃掉，只产出一个 `addCardToHand`（无名字），
引擎查不到卡只能报 undefined。全卡池 33 句「加入手牌」都走的是这条坏路径（有手写覆盖层的卡侥幸没暴露）。

**修法**：新增 `parseCardOp()`，抢在所有通用动作**之前**把这三类句式连同卡名一起解析：

| 卡面写法 | 结果 |
|---|---|
| `将三张经济复苏加入手牌` / `将两张“经济复苏”加入手牌` / `将四张「支援政策」加入手牌` | 名字 + 张数都对 |
| `将一张中环计划和一张经济复苏加入手牌` | 拆成**两张**不同的卡 |
| `随机将一张研发加入手牌`、`将一张随机Mk坦克加入手牌` | 在多个候选里**随机**取一张 |
| `将一张复制加入手牌`、`将一张所有数值减半的复制加入卡组顶` | 复制**这张卡自己**（以前也完全不生效） |
| `将两张“卡尔拉第二团”加入支援阵线` | 召唤 2 个（不是空放） |
| `将卡组顶的单位加入战场` | 卡组顶那张单位直接进场 |
| `将4张胁迫洗入卡组`、`将数张古洛亚飞艇洗入卡组` | 洗入卡组（张数不明时不乱猜） |
| `随机新星联盟太空单位加入支援阵线`、`将随机数量的联合国国家的卡牌洗入卡组` | 按**系列+兵种**随机取（不是卡名） |
| `抉择: 将三张黑盾单位加入手牌` | 类别名 → 运行时按"名称包含 + 只找单位"兜底 |

**运行时的取卡顺序**（`FX.opCardId`）：`cardId` → `self`（自己）→ 卡名（精确 → 别名 → 互相包含 → **名称包含**，
剥掉 `单位/卡牌/卡/牌` 后缀，`X单位` 只找单位）→ `filter`（按系列/兵种随机）→ 才记错误日志。
缺卡名时也会明确报「没写清楚是哪张卡」，不再出现「undefined」。

断言：*「将N张X加入手牌 / 加阵线 / 洗入卡组」真的拿到卡（不再有「undefined」）*——
除了 8 个运行时用例，还会**扫描全卡池文本**，确保没有一句会编出"没有卡名的 addCardToHand / shuffleIn"。
编译器自动解析率顺带从 72.4% 升到 **73.0%**。

## 3.27 「目标」与「单位」的区别（总部属于目标）

按你的说明：**总部属于「目标」**，所以目标的写法决定能不能指向总部。

| 卡面写法 | 能指向谁 |
|---|---|
| `对一个单位造成X点伤害` | **只有单位**——这就是"无法指向总部" |
| `对一个目标造成X点伤害` | 单位**或总部**（提示里总部可以直接点） |
| `造成X点伤害`（"造成"前面无条件） | 同「目标」：单位或总部 |
| `对所有敌方目标造成X点伤害` | 敌方所有单位 **+ 敌方总部** |
| `对所有目标造成X点伤害` | **双方**所有单位 + **双方**总部 |
| `对友方总部造成X点伤害` | 只打我方总部（以前只有"对敌方总部"能自动解析） |

顺带修掉两个毛病：

- `对敌方总部造成X点伤害` 以前**还会多问一次"选择单位"**（那个目标根本没人用）——现在 `damageHQ` 不再声明目标。
- 「所有目标」类句子的自动解析结果，已与手写的**奋起反抗**（双方单位+双方总部）、**空中打击**
  （敌方单位+敌方总部）完全一致：`damageAll` + `damageHQ`。

只有"造成伤害"会把总部列进候选；消灭 / 压制 / 增益对总部没有意义，仍然只列单位。

断言：*「目标」vs「单位」：总部属于目标，写「单位」就不能指向总部*（含真选一次敌方总部：20→17）。

## 3.26 新增「反制」卡牌种类 + 3 张卡改型

## 3.20 互伤是"同时结算"（UNTED-UJA-401 吃不到反击的真凶）

卡面：UNTED-UJA-401 是 4/3 战斗机（闪击 + "部署：本回合内无法攻击总部"），
它的攻击力 4 通常**一击就能打死对方**，而我的实现是"守方死了就不反击" → 于是它几乎永远吃不到反击。

而官方规则（RULES_REF 8.1）写的是**互伤同时结算**：
> 攻方对守方造成等同攻方攻击力的伤害，**同时**守方对攻方造成等同守方攻击力的伤害
> （结算上视为同时；防御力 ≤ 0 即被消灭）

修法：先算好守方的反击值，**即使守方会被这一击打死也照常打出反击**。
唯一的例外是伏击：伏击先手把攻方打死时，攻方不造成伤害（这条已单独处理）。
另外把"没有反击"的原因写进战报（不受反击 / 不造成反击 / 攻击力为 0），方便你核对。

断言：*互伤同时结算：守方被打死也会打出反击伤害*（古洛亚第32团 5 攻打死 Mk1(b)坦克 2/2，攻方掉血 2）✅

> 这也解释了你之前说的"一攻的反击伤害直接被吞了"——同一个原因（1 攻打不死人，但守方可能被打死）。

## 3.19 又是两类"全局事件"bug + 反击被吞的真凶

**① UNTED-236 的 +4 攻击力**：`mobilize`（移至前线）和 `deploy` 一样被当成了**全局事件** ——
所以"**你任何一个单位**上前线，UNTED-236 都会跟着 +1"，上前线 4 次就 +4（哪怕它自己一直待在支援线）。

- 修法：`mobilize` 改成**自身语义**（只有正在移动的那个单位自己的效果触发）
- "友方单位移至前线时"这类监听改用新触发器 `unitMobilized`，已迁移「国际后勤组织」

**② 反击伤害仍然被吞**：真凶是 `immuneUnitEffects`（"无视单位效果"）的实现 ——
它把**战斗伤害也一起免疫了**，所以带这个词条的单位：
普攻打不动它（重甲之外还整个免疫）、它也不吃反击、它的反击也被别人免疫吃掉。

- 修法：`immuneUnitEffects` / `ignoreEnemyEffects` **只挡"单位技能造成的伤害/效果"**，
  **不挡战斗伤害、也不影响反击**（战斗伤害调用都带 `combat:true` 标记）

**③ 顺带修掉的重复计算**：`takeDamage`（"对战坦克伤害减1"）在攻击力计算和伤害结算里各算一次
→ 攻击力 2 的单位打它会变成 0 伤害。现在只在伤害结算里算一次。

对应断言 3 条：*别人上前线不会给 UNTED-236 加攻击力，只有它自己上前线才加*、
*「友方单位移至前线时」监听效果正常触发*、*「无视单位效果」不会免疫战斗伤害，也不会吞掉反击伤害*。

> 说明：鳄龟坦克被"打不动"其实有一半是它自带**重甲3**（正常规则），测试里已按护甲口径校验。

## 3.16 「部署：」的重复触发 bug（你发现的）

`playCard` 里除了执行新单位**自己**的「部署：」效果，还额外派发了一次全局 `deploy` 事件
→ 结果**别人身上的「部署：」效果会跟着再触发一遍**。

- 现象：你部署「部署：与一个敌方单位战斗」的单位后，之后每部署一个新单位，它都会再打一次；
  蜂鸟突击舰同理 —— 每次部署别的单位都会重复给「经济复苏」，所以一回合内手上会多出好几张。
- 修法：删掉那次全局 `deploy` 派发；「部署：」只属于刚上场的那个单位（和亡计一样是"自身语义"）。
  「友方单位部署时…」这类监听统一用 `trigger:'unitDeployed'`（反制措施里写 `on:'deploy'` 的也已兼容映射到该事件）。
- 数据侧用 `node game/tools/fix-deploy-trigger.js` 全池扫描：0 处需要迁移，44 处「部署：」保持自身语义。

断言：*部署新单位不会重复触发别人身上的「部署：」效果*（经济复苏 0→0、UNTED-K904 4→4、蜂鸟突击舰 8→8）、
*「友方单位部署时」监听效果正常触发*、*反制措施：埋伏并在对手部署时触发*。

> 副作用（正常）：之前"部署效果重复触发"等于让所有卡组强度虚高，修好后对局变长了一些
> （AI 对局平均结束回合 17 → 35）。想更快节奏可以调低总部血量或提高 AI 难度。

## 3.14 亡计 vs "友方单位被消灭时"（按你的说明）

| 卡面写法 | 触发器 | 语义 |
|---|---|---|
| **亡计：…** | `trigger:'death'` | **只有本单位死亡时**触发 |
| **友方单位被消灭时…** | `trigger:'friendlyDeath'` | 监听"己方任意单位死亡"，是另一种效果 |

之前为了让"友方单位被消灭时"能生效，我让 `death` 触发器在别的单位死亡时也会被匹配 ——
结果是**所有亡计会互相触发**（一个单位死了，别人身上的亡计也跟着炸）。现在两者彻底分开：

- `death` 只在 `killUnit()` 里对"死者自己"派发一次
- `friendlyDeath` 单独派发，**不会**匹配 `death`

数据侧已用 `node game/tools/fix-death-trigger.js` 全池扫过：3 处"友方单位被消灭时"改成了 `friendlyDeath`
（解体、北极星计划的总部附魔、第939特种步兵团），10 处标准亡计保持不动。

对应断言：*亡计只在本单位死亡时触发（别人死了不会连带触发）*、
*"友方单位被消灭时"是监听效果，别人死亡时会触发*（总部上限 20→22）。

## 3.13 两种"免疫指令"的区别（按你的说明）

## 3. 导入自己的新卡

1. 把卡图 PNG 放进任意文件夹，点界面「卡牌库 / 导入 → 选择文件夹 / 文件」。
2. 若该文件夹有 `cards.json`，会自动读取；格式：

```json
{ "cards": [
  { "id": "my/1", "name": "虎式坦克", "set": "自定义", "cardType": "unit", "unitType": "tank",
    "cost": 5, "attack": 6, "defense": 5, "opCost": 2, "keywords": ["guard"],
    "text": "部署：对一个敌方单位造成2点伤害。",
    "effects": [ { "trigger": "deploy",
                   "targets": [{"id":"t","side":"enemy","kind":"unit"}],
                   "actions": [{"op":"damage","target":"t","amount":2}] } ] }
] }
```

3. 没有 `cards.json` 也能玩：点开卡牌 → 填费用/攻防/词条/效果文本 → 点「自动解析效果」，
   常见句式（`抽N张牌`、`对X造成N点伤害`、`消灭一个敌方单位`、`使所有X获得+2+2`、`压制`、
   `洗入卡组`、`部署：…`、`亡计：…`、`抉择：…`）会自动变成可执行效果。
4. 解析不了的部分会留在「效果 DSL」框里，可以直接手改（规范见 `game/data/EFFECT_DSL.md`）。
5. 保存后立刻在对战里生效；「导出 cards.json」可以把整池数据导出备份。
